About the Project

From-scratch cryptographic file-transfer stack in C. I implement bignum RSA (1024/2048), SHA-256, AES-128-CBC with HMAC-SHA256, RSA-OAEP, RSA-PSS, and a tiny X.509/DER parser for a CA-anchored handshake. No external crypto libraries; just libc and POSIX.

Security notes — Educational project. Constant-time and side-channel hardening are out of scope. CA root is 2048-bit; server key is 1024-bit zero-extended to 2048-bit math for a single code path.

Highlights

  • Single bignum backend (2048-bit limbs) — handles CA(2048) and server(1024).
  • RSA core + OAEP (enc) and PSS (sign) per RFC 8017 (SHA-256).
  • AES-128-CBC with PKCS#7 and HMAC-SHA256 (AE wrapper) for streaming.
  • Minimal DER walker: extracts SPKI and verifies cert signature (v1.5).
  • AP/CP protocols over TCP: AP handshake, CP1 (RSA-only), CP2 (hybrid AES).
  • Key tools: csrgen (PKCS#1 private key + PKCS#10 CSR), dump_ca_pub.
  • Strict build: -Wall -Wextra -Werror, optional asan=1.

Protocols

  • AP: Client verifies server cert with CA root; server PSS-signs challenge.
  • CP1: RSA-OAEP per-chunk (≤ 62 B at 1024-bit) — correctness baseline.
  • CP2: RSA-OAEP wraps {AES key, HMAC key}; data via AES-CBC + HMAC.

Build & Run

# Build (debug + sanitizers optional)
make debug=1 asan=1

# Format the tree
make format

# Generate server key header (once you hook up keygen)
make keygen

# Run server and client
make run-server PORT=9000
make run-client HOST=127.0.0.1 PORT=9000 FILE=README

Keys live in keys/. CA root (2048-bit) is embedded as limbs; server keypair (1024-bit) is zero-extended to the 2048-bit bignum size.

Repository Layout

include/   bn.h, crypto.h, sftp.h
keys/      ca_pub.h (root), server_keys.h (your server keypair)
src/       bn.c, sha256.c, aes.c, crypto.c, ap.c, cp1.c, cp2.c, net.c,
       main_server.c, main_client.c, csrgen.c, keygen.c
tests/     t_sha256.c, t_aes.c, t_bn.c, t_rsa.c
misc/      dump_ca_pub.c, helpers (hex converters), CA cert
Makefile   strict flags, format, test, run targets
